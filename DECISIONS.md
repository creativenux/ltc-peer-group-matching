# Decisions

The design decisions I made while building the system, and the reason for each.

| # | Decision | Reason |
|---|---|---|
| 1 | The system has a **FastAPI** backend, an **HTML and Tailwind CSS** web interface, and **command-line** scripts. | The web interface lets the supervisor and marker run each stage live. The command line makes every result reproducible without a browser. |
| 2 | The code keeps a flat layout: the generator in `/dataset_generation`, the matching method in `/matching`, the evaluation in `/evaluation`, the tests in `/tests`. `paths.py` adds `/dataset_generation` to the import path. | The generator files import each other by name (`from schema import ...`), so they work without changes. Their generation logic is the version my supervisor reviewed. |
| 3 | The evaluation uses **20 datasets of 3,000 profiles**. The 50,000-profile dataset is used only to validate the generator. | At 3,000 profiles the largest pool has about 730 people, so matching stays fast: all five methods run in about 26 seconds per dataset, and the full evaluation in about 6 minutes. |
| 4 | The **number of groups** in a pool of n people is round(n/7), kept within [ceil(n/8), floor(n/6)]. When no valid number exists (n = 9, 10, 11 or 17), I form as many groups of 8 as possible and record the rest as `remainder_not_absorbable`. | This aims for groups of seven and guarantees every group has 6 to 8 members, without forcing anyone into a group of the wrong size. |
| 5 | In the **greedy step**, a profile joins the open group where it adds most: (sum of homogeneity weights) × (1 − mean Gower distance to the members), plus the change in entropy. | A change in Score(G) cannot be computed for a one-member group, because it has no pairs. This form works at every group size. |
| 6 | The greedy step takes the pool in a **seeded random order**. The first k profiles start the k groups, and the order is logged. | No starting order is better than another, so it is made reproducible and recorded. |
| 7 | Each **local-swap pass** scores every swap between members of different groups at once, then applies the best improving swaps, at most one per group. A test checks the scores against full recomputation. | One swap per group keeps each gain exact, and scoring all swaps at once keeps the run time low. The total score always rises, so the process always stops. Every pool converged within 34 passes (limit 200). |
| 8 | Swaps happen **only between grouped members**. People left over by the size plan are not swapped in. | The swap step only rearranges groups. Leftovers only occur in pools of 9, 10, 11 or 17. |
| 9 | The **single-attribute baseline** shuffles the pool before sorting on the attribute. | Without the shuffle, ties would keep the order the generator produced them in. |
| 10 | In the **random and single-attribute baselines**, the leftovers are the last profiles in the shuffled or sorted order. | Every method uses the same group sizes, so the number of unmatched people is the same for every method. |
| 11 | Group scores for the **random and single-attribute baselines** use the default weights, and the evaluation scores every method the same way. | Scores can only be compared if they are computed the same way for every method. |
| 12 | A group's **balance** is described from its entropy: 0.75 or more is "well balanced", 0.40 or more is "partly mixed", below that is "dominated by one …". | There are no standard cut-offs, so these are my choice. |
| 13 | When two attributes **tie** in an explanation, the one with the higher weight is named first. | The explanation is the same every time, and it names the attribute the method values most. |
| 14 | The **adult rule** is checked and logged even though it never excludes anyone. | Every rule should be visible in the log, not only the ones that exclude people. |
| 15 | **All results go to `/output`**: datasets to `/output/n<n>`, matching results to `/output/matching`, evaluation results to `/output/evaluation`. The locations are set once in `paths.py`. | Every part of the system reads from one place. A folder per size stops datasets of different sizes overwriting each other, because file names only contain the seed. |
| 16 | **Silhouette** is computed within each pool on grouped profiles, then averaged, weighted by the number of grouped profiles. Pools with one group are skipped. | Groups never cross pools, so silhouette only makes sense within a pool. Weighting stops small pools counting as much as large ones. |
| 17 | Silhouette is reported on **both the weighted and the unweighted Gower matrix**. | The weighted method optimises the weighted matrix, so it is favoured there. The unweighted matrix checks that its lead over the baselines does not depend on this. |
| 18 | Each metric is tested with a **Friedman test** (effect size Kendall's W), then **Wilcoxon signed-rank tests** of the weighted method against each baseline with **Holm correction** (effect size: matched-pairs rank-biserial correlation). The unmatched rate is the same for every method in every dataset, so it is reported but not tested. | Every method is run on the same datasets, so a paired, non-parametric test fits. Holm correction allows for the four comparisons. |
| 19 | The **sensitivity analysis** also measures each grouping's within-group distance under the original weights, and compares two runs that differ only in seed. | The Adjusted Rand Index shows how much membership changes, not whether groups get worse. The seed comparison shows how much membership changes for reasons unrelated to the weights. |
| 20 | The **group map** places people by classical multidimensional scaling (Torgerson, 1952) of the weighted Gower distances and draws a line from each member to their group's centre. | It gives the same picture every time and shows cohesion directly: short lines mean a close group. It is for display only. |
| 21 | The web interface generates datasets and runs matching directly, but runs the **evaluation in the background** with a live log. Matching is limited to 10,000 profiles and the evaluation to 5,000. | Generation and matching take seconds; the evaluation takes minutes. The limits keep waiting times reasonable. |
| 22 | The online version runs in **read-only mode** (`READ_ONLY=1`) and shows results committed to the repository: the 3,000-profile dataset with seed 42, its matching results and the evaluation. | The free hosting has little memory and processing power, and the online version is for viewing results, not running experiments. Committing one reference run keeps the repository small. |
